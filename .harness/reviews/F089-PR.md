# F089 — Failure Simulation — Pull Request

## Summary

Implements the Architecture Failure Simulation Engine for DiagramHQ (Phase 11 — Drift and Governance).

## Changes

### Domain (`packages/domain/src/`)

**`failure-simulation.ts`** (264 lines):
- `simulateFailure(model, config)` — simulates component outages on one or more model objects, cascades the failure to upstream dependents using reverse BFS blast-radius analysis, and classifies each node status as `down`, `degraded`, `fallback`, or `healthy`.
- Distinguishes nodes with fallback mechanisms (`status: 'fallback'`) versus unmitigated dependencies (`status: 'degraded'`).
- `getAffectedConnections(model, report)` — surfaces connections disrupted by the simulated outage.
- Computes comprehensive simulation metrics: `totalDownedNodes`, `totalDegradedNodes`, `totalFallbackNodes`, `totalHealthyNodes`, `impactedCustomerFacingCount`, `impactedTeamCount`, `maxCascadeDepth`, and `hasFullOutage`.

**`failure-simulation.test.ts`** (203 lines): 3 unit tests
- ✓ Simulates a DB outage: downstream nodes flagged, fallbacks distinguished
- ✓ Distinguishes fallback vs no-fallback nodes in simulation
- ✓ getAffectedConnections returns only connections touching downed/degraded nodes

**`index.ts`**: Exports `./failure-simulation`

### Web (`apps/web/`)

**`components/canvas/failure-simulation-panel.tsx`** (525 lines): `<FailureSimulationModal />`
- Multi-downed node selector with quick toggle and custom failure reason input
- Severity banner (critical/high/medium/low) with outage diagnosis
- 6 KPI metric cards: Downed Nodes, Degraded (No Fallback), Fallback Active, Healthy Nodes, Customer Facing, Max Cascade Depth
- Filter tabs: All, Impacted, Down, Degraded, Fallback, Healthy + node search
- Impacted node list with status badges (`DOWN`, `DEGRADED`, `FALLBACK ACTIVE`, `HEALTHY`), fallback indicator (`FALLBACK READY` vs `NO FALLBACK`), cascade reason, hop distance, and quick restore / mark-down toggle
