# Pull Request: F137 — Inline Rename & Edge Labels

## Summary
Implements F137 from Phase 14 (UX Remediation). Eliminates the frequent high-interaction friction of renaming objects and labelling connections by adding inline editing with instant double-click affordances and full command stack undo/redo support:

- **Inline Node Rename (≤ 2 interactions)**:
  - Double-clicking any canvas node or its label text switches into edit mode.
  - Automatically focuses and selects the draft text.
  - Pressing `Enter` or blurring commits the rename.
  - Pressing `Escape` cancels and restores the original name.
  - Created reusable client component `EditableNodeLabel` integrated across all standard node types (`AppNode`, `SystemNode`, `DatabaseNode`, `QueueNode`, `ComponentNode`, `PersonNode`, `GroupNode`, `StoreNode`) and C4 nodes (`C4ContextNode`, `C4ContainerNode`, `C4ComponentNode`).
- **Inline Edge Labelling (≤ 2 interactions)**:
  - Double-clicking the edge path (via expanded 24px invisible hit area) or the centered pill badge opens the inline label editor directly at the edge midpoint `(labelX, labelY)`.
  - Pressing `Enter` or blurring commits the new label and description.
  - Pressing `Escape` cancels and restores original label.
- **Undoable Command Stack**:
  - Commits route through `defaultCommandDispatcher` with `UpdateNodeMetadataCommand` and newly introduced `UpdateEdgeDataCommand`.
  - Pressing `⌘Z` / `Ctrl+Z` reverts either rename or edge labelling; `⌘⇧Z` redoes.
- **Inspector Synchronization**:
  - Inspector editing remains in sync through `canvas:node-rename` and `canvas:edge-label-change` window event dispatchers and `onNodeRename`/`onEdgeLabelChange` callbacks.
- **Canvas Keybinding Isolation**:
  - Inputs carry `nodrag` and `nopan` classes and stop propagation, honoring `isTextInput` guards in `infinite-canvas.tsx` so backspace/delete keys do not delete canvas objects while editing.
