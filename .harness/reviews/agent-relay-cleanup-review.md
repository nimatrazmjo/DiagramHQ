## PR Review — round 1 (code-review skill, PR #3)
3 findings: `cleanup()` only killed the `caffeinate` helper, never the foreground `claude`/`agy` child — a SIGTERM sent to just the wrapper's PID (not a terminal Ctrl-C, which reaches the whole process group) would leave that child running orphaned; `RUNTIME-CONTINUITY.md`'s new note claimed `pnpm install` alone "rebuilds ... Prisma engine for this platform", contradicting this repo's own `init.sh`, which runs `prisma generate` as a separate step; this harness-only change had no `CHANGELOG.md` entry, violating `conventions.md`'s own session-hygiene rule.

All 3 fixed: `claude`/`agy` are now launched backgrounded (`&` + `wait`) so their PID is capturable, and `cleanup()` kills that PID too — smoke-tested the background+wait+signal-forward pattern in isolation (SIGTERM to the wrapper correctly kills the backgrounded child, verified via `ps` before/after); `RUNTIME-CONTINUITY.md` now calls out `pnpm prisma:generate` as a required second step, not implied by `pnpm install`; added the missing `CHANGELOG.md` entry (this file's own citation). `bash -n scripts/agent-relay.sh` clean.

## PR Review — round 2 (code-review skill, PR #3)
4 findings: `cleanup()` only killed the immediate `claude`/`agy` child, not any grandchildren it spawns (MCP subprocesses etc.); it killed with a bare SIGTERM, and many TUIs only special-case SIGINT to restore terminal state before exiting; a narrow TOCTOU window between `wait` returning and `RUNTIME_PID` being cleared; the background+wait+reset pattern was duplicated verbatim between the `claude` and `agy` branches.

2 of 4 fixed in `6ea514d`: SIGINT-then-SIGTERM escalation with a 0.3s grace period; extracted `run_and_wait()` to remove the duplication. The other 2 are documented tradeoffs, not fixed: signaling grandchildren would need process-group isolation (`set -m`), which makes the kernel stop a backgrounded group on tty access (SIGTTIN) — breaking `claude`/`agy`'s interactive terminal ownership, a worse regression than the theoretical leak; the TOCTOU window is accepted as-is (a `ps`-based liveness check to close it isn't worth the complexity for a single-operator local dev script). Both are called out in code comments at the relevant lines, not silently dropped. Tried to smoke-test the SIGINT escalation directly; this sandboxed tool environment's signal delivery to backgrounded external processes didn't reliably reproduce a trap firing in isolation (separate repro attempts showed inconsistent results even for a script's own SIGINT trap), which looks like an artifact of the sandbox rather than the script — the underlying kill/wait mechanics were already proven working in round 1's smoke test, and `kill -INT; sleep; kill -TERM` is a standard, widely-used escalation pattern. `bash -n` clean; `pnpm verify` clean (21 tests, unrelated to this script).
