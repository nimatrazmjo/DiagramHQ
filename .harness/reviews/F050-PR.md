# F050 — Comments

## Description
This PR implements F050 — Comments (Phase 06 — Collaboration).

Supports threaded comments across architectural entities (objects, connections, diagrams, flows, docs, and changes) with reply, resolve, and re-open workflows:
- Pure domain engine in `packages/domain/src/comments.ts`:
  - `CommentTargetType`: `'object' | 'connection' | 'diagram' | 'flow' | 'doc' | 'change'`.
  - `createComment()`: creates root comments on any target entity, validating input non-emptiness.
  - `replyToComment()`: creates threaded replies nested under the root comment.
  - `resolveComment()`: marks threads resolved with resolver identity and timestamp.
  - `reopenComment()`: restores threads to active status.
  - `updateCommentContent()`: updates comment text.
  - `filterComments()`: filters by targetType, targetId, resolved status, and authorId.
  - `buildCommentThreads()`: aggregates root comments with chronologically ordered replies.
  - `countUnresolvedCommentsByTarget()`: computes badge counts for canvas overlays.
- Unique ID branding: added `'cmt'` prefix and `CommentId` to `packages/domain/src/ids.ts`.
- Canvas UI components in `apps/web/components/canvas/`:
  - `<CommentsPanel />`: collapsible drawer displaying entity badge, Open vs All toggle, thread cards with author initials, resolve/reopen buttons, replies list, reply composer, and new thread composer.
  - `<CommentPinBadge />`: unobtrusive bubble indicator on canvas objects/connections showing unresolved comment count (`💬 N`).
- Comprehensive testing:
  - 7 unit tests in `packages/domain/src/comments.test.ts`.
  - 5 integration tests in `apps/web/comments.spec.tsx`.
