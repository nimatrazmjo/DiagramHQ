## Summary of Changes

Implements **F004 — Workspaces** from Phase 01 (Foundation):
- **API Layer (`apps/api`)**:
  - Implemented `WorkspacesModule`, `WorkspacesService`, and `WorkspacesController`.
  - Added endpoints:
    - `POST /organizations/:orgId/workspaces`: Creates a workspace within an organization; validates org membership and roles (`owner`, `admin`, `editor`); enforces unique slug per org (`@@unique([orgId, slug])`).
    - `GET /organizations/:orgId/workspaces`: Lists workspaces belonging to the organization with `_count.architectures`.
    - `GET /workspaces/:id`: Returns workspace details with contained architectures and caller's member role (404 for unassociated callers).
    - `PATCH /workspaces/:id`: Updates name, slug, and settings (guarded to `owner`, `admin`, `editor` roles).
    - `DELETE /workspaces/:id`: Deletes workspace and cascades deletion to architectures (guarded to `owner` and `admin` roles).
    - `GET /workspaces/:id/architectures`: Lists architectures contained within the workspace.
  - Implemented input validation with `CreateWorkspaceDto` and `UpdateWorkspaceDto`.
  - Added unit test suite in `workspaces.service.spec.ts` (25 tests).
  - Added e2e integration test suite in `workspaces.e2e.spec.ts` (14 tests) verifying CRUD, architecture containment, slug collisions, and cross-tenant isolation against live PostgreSQL.
- **Web Layer (`apps/web`)**:
  - Added server actions in `app/dashboard/workspace-actions.ts` (`createWorkspaceAction`, `fetchOrgWorkspaces`).
  - Added `CreateWorkspaceForm` client component with validation and user feedback.
  - Added `WorkspaceList` component displaying workspace metadata and architecture count badge.
  - Updated `/dashboard` page to load and display workspaces per organization.
  - Added unit test suite in `workspaces.spec.ts` (11 tests).
