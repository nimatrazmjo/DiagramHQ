# F090 — Security Architecture — Pull Request

## Summary

Implements the Security Architecture Engine and Governance Analysis for DiagramHQ (Phase 11 — Drift and Governance).

## Changes

### Domain (`packages/domain/src/`)

**`security-architecture.ts`** (470 lines):
- Deep security architecture model and analysis engine:
  - Discovers **Trust Boundaries** with isolation levels (`untrusted`, `dmz`, `trusted`, `restricted`, `critical`) and enclosed components.
  - Identifies **Public Endpoints** and audits authentication schemes (OAuth2, JWT, API Key, mTLS).
  - Detects **Sensitive Data Stores** (PII, PCI, HIPAA, GDPR, SOC2) and evaluates encryption at rest (e.g. AES-256).
  - Analyzes **Secrets Management** (identifying hardcoded credentials vs managed secret stores like HashiCorp Vault or Cloud KMS).
  - Identifies **Cross-Boundary Connections** and flags unencrypted plaintext transit (missing TLS) or unauthenticated ingress to restricted zones.
  - Automatically maps **Compliance Zones** for regulatory frameworks (PII, PCI, HIPAA, GDPR, SOC2).
  - Computes comprehensive security metrics and a normalized **Security Score** (0-100) penalized by exposure severity.

**`security-architecture.test.ts`** (220 lines): 3 unit tests
- ✓ Renders boundaries and flags exposures on public endpoints, unencrypted PII/PCI stores, and unencrypted transit
- ✓ Correctly maps compliance zones for PII, PCI, and HIPAA
- ✓ Evaluates clean, fully compliant architecture with 100 security score

**`index.ts`**: Exports `./security-architecture`

### Web (`apps/web/`)

**`components/canvas/security-architecture-panel.tsx`** (740 lines): `<SecurityArchitectureModal />`
- Security health banner with score badge (0-100), critical/high warning badges, and diagnosis
- 6 KPI metric cards: Security Score, Trust Boundaries, Public Ingress, Sensitive Stores, Cross-Boundary Links, Exposures
- 6 navigation tabs with search filtering:
  - **Exposures**: Severity badges (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`), remediation advice, compliance impacts, and clickable target buttons
  - **Trust Boundaries**: Boundary zones, isolation levels, and enrolled components
  - **Public Endpoints**: Ingress routes, authentication schemes, and `SECURED` vs `UNAUTHENTICATED` badges
  - **Data Encryption**: Storage at rest status (`AES-256`) and sensitive classification tags
  - **Compliance Zones**: PII, PCI, HIPAA, GDPR, SOC2 enrollments and store counts
  - **Cross-Boundary Links**: Inter-zone network connections with TLS/auth status and risk level
- Search filter by component name, route, exposure title, or compliance tag
