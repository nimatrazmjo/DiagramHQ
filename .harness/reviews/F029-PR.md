## Description
Implements **F029 — Connections** from Phase 03 (Architecture Model): First-class connections with rich metadata properties, endpoints validation across same architecture and version, cycle/self-connection prevention, and model persistence.

- **Domain Layer (`packages/domain`)**:
  - `ConnectionProtocol`: HTTP, HTTPS, REST, GraphQL, gRPC, WebSocket, TCP, UDP, Kafka, Event, Queue, Database, File, Internal, External.
  - `ConnectionDirection`: unidirectional, bidirectional.
  - `ConnectionStatus`: active, deprecated, planned, unknown.
  - `ConnectionAuth`: none, api_key, oauth2, jwt, mtls, basic.
  - `ConnectionEncryption`: none, tls, mtls, custom.
  - `RichConnectionMetadata` interface: `protocol`, `technology`, `direction`, `dataType`, `auth`, `encryption`, `status`, `owner`, `tags`, `api`, `port`, `frequency`, `latency`, `errorBehavior`.
  - Helpers: `createRichConnectionMetadata`, `isRichConnection`, `RICH_CONNECTION_PROTOCOLS`.
  - Unit tests in `packages/domain/src/connection.test.ts`.
- **API Layer (`apps/api`)**:
  - 5 comprehensive E2E tests in `apps/api/src/architectures/connection.e2e.spec.ts` covering:
    - Connection creation with rich metadata (protocol, auth, encryption, port).
    - Validation that source and target must exist in the same architecture and version (cross-architecture connection rejected with HTTP 400).
    - Validation that self-connections are rejected (HTTP 400).
    - Metadata updates via `PATCH /connections/:id` (latency, errorBehavior).
    - Verification that architecture model reload reflects connections with rich metadata.
- **Test Infrastructure (`apps/api/vitest.config.ts`)**:
  - Disabled `fileParallelism` in `apps/api` to eliminate database connection pool contention across concurrent E2E test suites hitting local PostgreSQL.
