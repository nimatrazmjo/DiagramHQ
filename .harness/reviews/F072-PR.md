# Pull Request: F072 — GitHub

## Description
Implements GitHub repository connectivity and static code analysis for automated architecture discovery. Scans GitHub repository file trees (`package.json`, `docker-compose.yml`, route controllers) to identify services, exposed APIs, persistent datastores, message queues, frameworks, and cloud provider SDKs, while attaching verifiable grounding evidence (`AIEvidence`) and calibrated confidence scores (`ConfidenceAssessment`).

### Key Additions
1. **Domain Layer (`packages/domain/src/github-scanner.ts`)**:
   - `scanGitHubRepository(input)`: parses file trees statically to extract applications, API endpoints, stores (PostgreSQL, MySQL, Redis, MongoDB), and message brokers (Kafka, RabbitMQ).
   - Invariant enforcement: every detected entity and connection carries concrete code evidence (repo, file path, line numbers) and calibrated confidence assessment (high/medium/low).
   - All detected items are formulated as proposed additions for human-in-the-loop review before model import.
   - `packages/domain/src/github-scanner.test.ts`: 2 unit tests verifying that scanning sample repository trees extracts expected objects, datastores, queues, and frameworks with evidence and confidence scores.

2. **Web Layer (`apps/web/components/canvas/github-scanner-panel.tsx`)**:
   - `<GitHubConnectModal />`: modal dialogue to specify GitHub repository (owner/repo or URL) and target branch/reference.
   - `<GitHubScanResultDrawer />`: comprehensive drawer presenting discovered services, APIs, datastores, and message queues with confidence badges, code citations, and one-click import into the architecture model.
   - `apps/web/github-scanner.spec.tsx`: 4 integration tests verifying end-to-end repository scanning, modal and drawer rendering, and empty states.
