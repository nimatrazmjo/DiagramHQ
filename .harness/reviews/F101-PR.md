# F101 — SSO — Pull Request

## Summary
Implements Enterprise Single Sign-On (SSO) with OpenID Connect (OIDC), OAuth2, and corporate Identity Provider (IdP) integration for DiagramHQ (Phase 13 — Enterprise). Delivers pure TypeScript domain logic for enterprise IdP provider configurations, corporate email domain auto-routing and discovery, strict SSO enforcement policies, cryptographically secure PKCE challenges and nonces, OIDC claim normalization, group-to-role attribute mapping, Just-In-Time (JIT) user provisioning, and a deterministic Test IdP simulation harness. Integrates SSO authentication seamlessly into NextAuth and the DiagramHQ Web login experience with dedicated password/SSO modes, real-time enterprise domain detection, 1-click Test IdP authentication, and an enterprise IdP administration settings modal.

## Changes

### Domain (`packages/domain/src/`)
- **`ids.ts`**: Added `idp` and `sso` prefixes to `IdPrefix` and defined branded ID types `SsoProviderId` and `SsoSessionId`.
- **`sso.ts`**: Pure TypeScript enterprise SSO domain module:
  - **Provider Configuration (`SsoProviderConfig`, `validateSsoProviderConfig`)**:
    - Organization identity provider model supporting OIDC, OAuth2, and Mock IdP architectures.
    - Configurable endpoints (`issuerUrl`, `authorizationEndpoint`, `tokenEndpoint`, `userinfoEndpoint`, `jwksUri`).
    - Corporate domain matching (`domains`: e.g. `acme.com`, `acme-enterprise.com`).
    - Lifecycle status management (`active`, `inactive`, `testing`).
    - Governance controls: `enforceSso` (prohibits password authentication for corporate email domains) and `allowJitProvisioning` (provisions users on first successful login).
  - **Domain Discovery & Routing (`findSsoProviderForEmail`, `isSsoEnforcedForEmail`, `normalizeDomain`, `extractDomainFromEmail`)**:
    - Auto-routes corporate email addresses to matching active SSO providers.
    - Evaluates strict SSO enforcement policies.
  - **PKCE & State Challenge Engine (`generateSsoChallenge`, `generateRandomToken`)**:
    - Generates cryptographically secure `state`, `nonce`, and PKCE `code_verifier`/`code_challenge`.
    - Constructs standards-compliant OIDC authorization redirect URLs.
  - **Claims & Attribute Mapping (`extractSsoClaims`, `mapSsoClaimsToRole`, `DEFAULT_SSO_ATTRIBUTE_MAPPING`)**:
    - Normalizes raw IdP claims (`sub`, `email`, `name`, `groups`, `roles`).
    - Maps enterprise IdP security groups and roles to DiagramHQ `MemberRole` (Owner, Admin, Editor, Viewer, Guest).
  - **Just-In-Time (JIT) Provisioning & Session Management (`provisionSsoUser`, `processSsoCallback`)**:
    - Creates new user identities with branded `usr_` IDs or links existing accounts by email.
    - Validates CSRF state and challenge expiration.
    - Generates 8-hour enterprise SSO authentication sessions (`SsoAuthSession`).
  - **Deterministic Test IdP Harness (`createTestIdpConfig`, `simulateTestIdpLogin`)**:
    - Complete simulated IdP for automated testing, developer workflows, and local test verification without external network dependencies.
- **`sso.test.ts`**: 19 unit tests verifying provider validation, domain normalization/routing, SSO enforcement checks, PKCE challenge generation, group-to-role attribute mapping, JIT provisioning, existing user linking, callback error validation (invalid code, state mismatch, expired session), and full Test IdP simulation.
- **`index.ts`**: Exported `sso`.

### Web (`apps/web/`)
- **`auth.config.ts`**:
  - Registered pre-configured enterprise demo SSO providers (`Acme Enterprise Okta`, `Stark Industries Entra ID`, `Strict Corp IdP`).
  - Enhanced `authorizeUser` to process enterprise SSO assertions and simulate Test IdP authentication.
  - Enforced enterprise SSO security policy: blocks password-based authentication when email belongs to a domain with `enforceSso: true`.
  - Propagates SSO provider identity in JWT tokens and user session payloads.
- **`auth.spec.ts`**:
  - Added test cases verifying SSO authentication via Test IdP.
  - Added test case verifying blocked password login for SSO-enforced corporate domains.
- **`components/enterprise/sso-settings-modal.tsx`**: `<SsoSettingsModal />`:
  - 3 Tabs: `Configured IdPs`, `⚡ Test IdP Simulation`, `+ Add Provider`.
  - Configured IdPs Tab: Displays active/inactive providers, corporate domains, SSO enforcement badges, and toggles for status and enforcement.
  - Test IdP Simulation Tab: Interactive test harness enabling admins to test any user email, simulate OIDC code exchange, and view verified session details in real-time.
  - Add Provider Tab: Form to configure new corporate IdPs (OIDC, OAuth2, Test IdP) with validation, discovery URL, client ID, domains, default roles, and governance toggles.
- **`components/enterprise/index.ts`**: Exported enterprise components.
- **`app/login/login-form.tsx`**:
  - Added `Password` vs `Enterprise SSO` authentication mode tabs.
  - Enterprise SSO Tab: Corporate email input with live IdP auto-detection indicator (e.g. `Acme Enterprise Okta`), "Continue with Single Sign-On", 1-Click "⚡ Sign In with Test IdP (Acme Enterprise)", and sample enterprise profiles.
  - Added direct launcher for Enterprise SSO Settings modal.
- **`sso.spec.tsx`**: 6 integration tests verifying LoginForm rendering with Password and Enterprise SSO modes, SsoSettingsModal open/closed states, enforcement badges, and end-to-end Test IdP simulation.
