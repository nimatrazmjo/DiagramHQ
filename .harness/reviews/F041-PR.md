# F041 — Flow model

## Description
This PR implements F041 — Flow model, the first feature of Phase 05 (Flows).

Flows represent ordered sequences of connections in an architecture model with playback capability (differentiating DiagramHQ from static diagram tools).

### Changes

**Domain layer (`packages/domain/src/`)**
- Added `flow.ts` containing:
  - `CreateFlowStepInput`, `CreateFlowInput`, `UpdateFlowInput`
  - `validateFlowSteps(steps, availableConnections)` — validates that every step references an existing connection in the architecture
  - `createFlow(input, availableConnections)` — builds a validated flow with ordered steps
  - `updateFlow(flow, input, availableConnections)` — updates flow metadata and replaces/validates steps
  - `getFlowConnections(flow, connections)` — resolves the ordered sequence of ModelConnection objects for playback/visualization
  - `reorderFlowSteps(steps, orderedConnectionIds)` — re-indexes steps per new sequence
- Updated `types.ts` — added `FlowStep` and `FlowWithSteps` interfaces
- Added `flow.test.ts` — 8 unit tests covering creation, validation, rejection of invalid steps, independent persistence from diagrams, resolving connections, updating, and reordering
- Updated `index.ts` — exports flow module

**API layer (`apps/api/src/`)**
- Added `flows/` module:
  - `flows.dto.ts` — `FlowStepDto`, `CreateFlowDto`, `UpdateFlowDto` with class-validator validation
  - `flows.service.ts` — full CRUD + connection existence verification within the architecture
  - `flows.controller.ts` — endpoints:
    - `POST /architectures/:architectureId/flows`
    - `GET /architectures/:architectureId/flows`
    - `GET /flows/:flowId`
    - `PATCH /flows/:flowId`
    - `DELETE /flows/:flowId`
  - `flows.module.ts` — NestJS feature module
  - `flows.service.spec.ts` — 8 unit tests covering all service methods and edge cases
- Registered `FlowsModule` in `app.module.ts`

**Web layer (`apps/web/`)**
- Added `flow-model.spec.ts` — 4 integration tests proving:
  1. Builds a flow as an ordered sequence of existing connections
  2. Rejects an invalid step referencing a non-existent connection
  3. Flow persists independently of diagrams and views
  4. Supports updating and reordering steps

## Acceptance Criteria Coverage

- ✅ **A flow is an ordered list of existing connections** — verified by domain `flow.test.ts`, API `flows.service.spec.ts`, and web `flow-model.spec.ts`.
- ✅ **Flow persists independently of diagrams** — verified in `flow.test.ts` and `flow-model.spec.ts` (flow references connections directly without view/diagram dependencies).
- ✅ **Test: build a flow from connections; an invalid step is rejected** — verified by tests in all layers (`INVALID_FLOW_STEPS` InvariantViolationError in domain, BadRequestException in API).
