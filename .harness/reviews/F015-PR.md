## Description
Implements **F015 — Auto-layout** from Phase 02 (Canvas): a layout-engine registry (MODULES.md §6) with 8 built-in engines, applied to the whole graph on demand.

- **Registry**: `registerLayoutEngine({ name, layout })` / `getLayoutEngine` / `listLayoutEngines` / `applyLayout` — core never switches on engine names; a plugin engine registers the same way as the built-ins.
- **Built-ins**: `grid` (row-major), `hierarchical`/`tree`/`layered`/`TB` (shared longest-path-from-root layering; a tree is just a DAG with no cross-branching), `LR` (same layering, axes swapped), `radial` (concentric rings from the same layering), `forceDirected` (deterministic spring simulation + guaranteed overlap-resolution pass).
- **No-overlap guarantee**: every engine is tested against a shared sample graph (including a deliberate 2-node cycle, to prove cyclic input degrades gracefully instead of hanging) with a bbox-overlap assertion — the phase file's literal acceptance test.
- **UI**: a bottom-left "Layout ▾" menu (shown once there are 2+ nodes) lists every registered engine; applying one dispatches `ApplyLayoutCommand` through the existing command layer.
