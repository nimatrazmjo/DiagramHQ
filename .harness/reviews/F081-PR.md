# Pull Request: F081 — Terraform

## Description
Terraform Infrastructure as Code (IaC) configuration parser and architecture mapping engine for DiagramHQ (Phase 10 — Infrastructure Integrations):
- HCL & State parsing engine:
  - Parses Terraform configurations (`.tf`, `.tfvars`) and state / plan JSON (`.tfstate`, `terraform show -json`).
  - Extracts resources (`resource "type" "name"`), data sources (`data "type" "name"`), modules (`module "name"`), outputs (`output "name"`), and variables (`variable "name"`).
  - Robust tokenizer handling nested blocks, attribute assignments, single/multi-line comments (`#`, `//`, `/* */`), string interpolations, and explicit `depends_on = [...]`.
- Multi-provider taxonomy recognition:
  - AWS: `aws_instance`, `aws_ecs_service`, `aws_lambda_function`, `aws_db_instance`, `aws_dynamodb_table`, `aws_s3_bucket`, `aws_vpc`, `aws_subnet`, `aws_sqs_queue`, `aws_sns_topic`, etc.
  - Azure: `azurerm_linux_virtual_machine`, `azurerm_app_service`, `azurerm_mssql_database`, `azurerm_storage_account`, `azurerm_virtual_network`, `azurerm_servicebus_queue`, etc.
  - GCP: `google_compute_instance`, `google_cloud_run_service`, `google_sql_database_instance`, `google_storage_bucket`, `google_compute_network`, `google_pubsub_topic`, etc.
  - Kubernetes: `kubernetes_deployment`, `kubernetes_service`, `kubernetes_namespace`, etc.
  - Generic fallback recognition based on semantic resource name keywords.
- Model mapping:
  - Maps resources to typed `ModelObject` records with kinds:
    - `'group'`: Virtual networks, subnets, Kubernetes namespaces, and modules (when `groupByModule` is enabled).
    - `'store'`: Relational databases, NoSQL tables, cloud storage buckets, caching clusters.
    - `'application'`: Compute instances, serverless functions, container services, API gateways, load balancers.
    - `'component'`: Messaging queues, event topics, streams, and worker tasks.
  - Module hierarchy: when `groupByModule` is enabled, modules become `kind: 'group'` objects, and resources declared inside modules have their `parentId` set to the module object.
  - Inter-resource connection inference: derives typed `ModelConnection` dependencies from HCL interpolations (e.g. `${aws_security_group.db_sg.id}`), module references, and `depends_on` lists, tagging appropriate protocols (`TCP : 5432`, `HTTPS / Storage API`, `AMQP / PubSub`).
  - Traceable IaC evidence: attaches `TerraformEvidence` (`sourceType: 'iac_terraform'`) with 1.0 confidence referencing resource address, provider, file path, and line numbers.
- Acceptance test verified: parsed a sample microservices Terraform repository with 4 HCL files across modules (network, database, compute) -> generated complete architecture model with 10+ objects, module groups, inferred connections, and evidence.
