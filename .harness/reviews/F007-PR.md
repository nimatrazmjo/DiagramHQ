# Pull Request: F007 — API foundation

Branch: `feat/F007-api-foundation` -> `main`

## Summary
Establishes the NestJS API edge foundation for DiagramHQ:
- Global `ValidationPipe` (`apps/api/src/common/validation.ts`): whitelist, reject unknown properties, transform — applied globally in `main.ts`.
- Global `AllExceptionsFilter` (`apps/api/src/common/http-exception.filter.ts`): every thrown error becomes the typed envelope `{ error: { code, message, details? } }`; unknown errors collapse to a generic 500 with no stack trace or internal detail reaching the client (logged server-side only).
- `/health` enhanced to check Postgres connectivity via `PrismaService.$queryRaw`; reports `ok`/`degraded` plus `checks.database`.
- `apps/api/src/app.e2e.spec.ts`: a real HTTP-level integration suite (`@nestjs/testing` + `supertest`) against the actual app — health, a 404's error envelope, and a throwaway DTO-validated route (not a permanent endpoint — domain CRUD lands in F003/F004) proving the ValidationPipe actually rejects/accepts through the real request pipeline.
- `apps/api/vitest.config.ts` + `unplugin-swc`: Vitest's default esbuild transform doesn't emit the `design:paramtypes` metadata NestJS's DI and `ValidationPipe` depend on. The new integration test caught this immediately (injected services were `undefined`, invalid payloads passed through unvalidated) — something unit tests of each class in isolation couldn't have caught.
