# F088 — Blast-Radius Analysis — Pull Request

## Summary

Implements the Architecture Blast-Radius Analysis Engine for DiagramHQ (Phase 11 — Drift and Governance).

## Changes

### Domain (`packages/domain/src/`)

**`blast-radius.ts`** (222 lines):
- `computeBlastRadius(model, targetNodeId, maxHops?)` — reverse BFS from the failing node using an inverted adjacency list; discovers all upstream dependents (nodes that have a dependency path to `targetNodeId`)
- `inferDependencyCategory` helpers: `isCustomerFacing`, `resolveHasFallback`, `resolveSeverity`
- Severity scoring: `critical` (customer-facing + no fallback) → `high` (customer-facing) → `medium` (≥3 services or critical path) → `low`
- Returns `BlastRadiusReport` with: `impactedNodes` (with hopCount, isCustomerFacing, hasFallback, team), `impactedFlows`, and `BlastRadiusMetrics` (impactedServiceCount, impactedDatabaseCount, impactedFlowCount, customerFacingCount, teamCount, hasCriticalPath, maxHops, severityScore)

**`blast-radius.test.ts`** (194 lines): 3 unit tests
- ✓ Computes blast-radius counts for a failing gateway node (services=1, customerFacing=1, flows≥2)
- ✓ Computes severity as critical when customer-facing and no fallback
- ✓ Returns low severity for isolated internal service with no upstream customer-facing nodes

**`index.ts`**: Exports `./blast-radius`
