# F035 — Dynamic views

## Summary
Implements live filtered projections (Dynamic Views) over the architecture model without persisting static object references in views.

- **Domain layer (`packages/domain/src/view-filter.ts`, `packages/domain/src/view.ts`)**:
  - Defined `ViewFilter` interface supporting 12 filter dimensions: team, technology, environment, domain, owner, status/lifecycle, tag/tags, criticality, data-classification, cloud, region, repository.
  - Implemented `matchesViewFilter(object, filter)` with multi-value array checks, normalized case-insensitivity, and fallback parent/container matching.
  - Implemented `evaluateDynamicView(objects, filter)` pure domain evaluation.
  - Added helper `createDynamicViewOptions` and type guard `isDynamicView`.
  - Comprehensive unit tests in `packages/domain/src/view-filter.test.ts` and `packages/domain/src/view.test.ts`.
- **API layer (`apps/api/src/views/`)**:
  - `views.service.ts`: Updated `getViewObjects` to dynamically project matching architecture model objects when a view contains a filter, preserving existing position overrides.
  - Added `getViewProjection` endpoint (`GET /views/:viewId/projection`) returning full view and projected objects with metadata and positions.
  - `dynamic-views.e2e.spec.ts`: 4 E2E integration tests verifying:
    1. Dynamic view creation with filter criteria (team, cloud, technology, environment, criticality).
    2. Dynamic object projection via `GET /views/:id/objects` and `GET /views/:id/projection` without static object entries.
    3. Acceptance criteria: modifying an object's metadata via `PATCH /objects/:id` immediately causes it to enter or leave the dynamic view without modifying the view itself.
    4. Position persistence for dynamically projected view objects.
- **Web client layer (`apps/web/dynamic-views.spec.ts`)**:
  - Unit tests verifying domain filter evaluation, filter creation, and type discrimination in web.
