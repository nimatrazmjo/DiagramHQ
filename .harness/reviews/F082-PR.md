# Pull Request: F082 — Kubernetes

## Description
Kubernetes cluster topology and workload manifest import engine for DiagramHQ (Phase 10 — Infrastructure Integrations):
- Multi-document YAML & manifest parser:
  - Parses multi-document Kubernetes YAML manifests (`---`).
  - Supports all 14 canonical Kubernetes resource types:
    - Logical & Multi-tenant Grouping: `Cluster`, `Namespace`
    - Workloads: `Deployment`, `StatefulSet`, `DaemonSet`, `Job`, `CronJob`, `Pod`
    - Networking & Proxies: `Service` (ClusterIP, NodePort, LoadBalancer), `Ingress`
    - Configuration & Persistent Storage: `ConfigMap`, `Secret`, `PersistentVolumeClaim` (PVC), `PersistentVolume` (PV)
- Architecture model mapping:
  - Maps resources to typed `ModelObject` instances:
    - `'group'`: Cluster and Namespace objects (provides multi-tenant namespace boundary containment).
    - `'store'`: ConfigMaps, Secrets, PVCs, and PVs.
    - `'application'`: Workloads (Deployments, StatefulSets, CronJobs, Pods) and routing ingress/services.
  - Multi-tenant namespace containment: workloads and namespaced resources have `parentId` set to their enclosing Namespace group object.
- Topology connection inference:
  - Ingress -> Service: detects HTTP/HTTPS traffic routing rules across hosts and path backends (`spec.rules[*].http.paths[*].backend.service.name`).
  - Service -> Workload: matches service label selectors (`spec.selector`) against workload template labels (`spec.template.metadata.labels`) for TCP/UDP port dispatch.
  - Workload -> Storage: maps persistent volume mounts (`persistentVolumeClaim.claimName`) to PVC store objects.
  - PVC -> PV: maps storage bindings (`volumeName`) to PersistentVolume store objects.
  - Workload -> Configuration: maps environment and secret injections (`envFrom[*].configMapRef`, `envFrom[*].secretRef`, volumes).
- Traceable IaC evidence: attaches `KubernetesEvidence` (`sourceType: 'kubernetes_manifest'`) with 1.0 confidence referencing resource kind, name, namespace, apiVersion, file path, and line numbers.
- Acceptance test verified: parsed a sample production microservices Kubernetes stack (11 manifests) -> generated complete topology model with 10+ objects, namespace containment, 5+ topology connections, and evidence.
