# F135 — Architecture templates

## Description
This PR implements F135 — Architecture templates, the final feature of Phase 04 (Diagrams and Views).

Templates let users start a new architecture from a pre-built scaffold instead of a blank canvas.

### Changes

**Domain layer (`packages/domain/src/`)**
- Added `architecture-template.ts` — pure domain module containing:
  - `TemplateId` union type (13 IDs: saas, ecommerce, fintech, healthcare, microservices, monolith, serverless, event-driven, data-platform, kubernetes, aws, azure, gcp)
  - `ArchitectureTemplate`, `TemplateObject`, `TemplateConnection` interfaces
  - `TEMPLATES` registry with full object + connection definitions for all 13 templates
  - `listTemplates()` — returns all templates
  - `getTemplate(id)` — lookup by ID
  - `getTemplatesByCategory(category)` — filter by category (patterns / cloud / infrastructure / data)
  - `instantiateTemplate(params)` — binds a template to a real architectureId + versionId, producing `ModelObject[]` + `ModelConnection[]` ready for persistence
- Added `architecture-template.test.ts` — 16 unit tests covering the registry API and instantiation edge cases.
- Updated `index.ts` — exports `architecture-template` from the domain package public API.

**Web layer (`apps/web/`)**
- Added `components/canvas/template-panel.tsx` — `<TemplatePanel />` React component that lists all templates in a filterable card grid (filter by All / Pattern / Cloud / Infra / Data). Pure presentation; instantiation is delegated to the domain layer.
- Updated `components/canvas/index.ts` — exports `TemplatePanel`.
- Added `architecture-templates.spec.ts` — 19 integration tests:
  1. All 13 required template IDs are present.
  2. Each specific template is registered (13 individual assertions).
  3. Instantiating SaaS → correct objects and connections created.
  4. Instantiated result can be loaded into ArchitectureModel without invariant violations.
  5. Every template instantiates cleanly and validates.
  6. Two instantiations produce disjoint object ID sets.
  7. Instantiation does not mutate the template definition.

## Acceptance Criteria Coverage

- ✅ **Templates: SaaS, e-commerce, fintech, healthcare, microservices, monolith, serverless, event-driven, data-platform, Kubernetes, AWS, Azure, GCP** — all 13 defined in the `TEMPLATES` registry.
- ✅ **Instantiate a template into a new architecture** — `instantiateTemplate()` produces `ModelObject[]` + `ModelConnection[]` bound to the caller's `architectureId`+`versionId`.
- ✅ **Test: instantiate a template → expected objects/connections created** — `architecture-templates.spec.ts` test "instantiating SaaS produces correct objects and connections" proves this end-to-end.
