# PR: F061 — Merge

## Feature Summary
Implemented pure 3-way architecture branch merge engine and conflict detection system. Compares base ancestor, source feature branch, and target branch (main). Accurately detects merge conflicts on identical object IDs (concurrent modifications on the same object ID, concurrent additions with differing attributes, or modify/delete collisions). Provides automated and manual resolution strategies ('theirs', 'ours', per-entity manual selection). Upon clean merge or conflict resolution, updates main's architecture state while transitioning the source branch status to `'merged'`. Added UI components `<ConflictResolutionBanner />` and `<MergeBranchModal />`.

## Acceptance Criteria Verified
- [x] Merge a branch onto main; conflict detection on the same object id.
- [x] Acceptance Test: merge applies to main; a conflict is detected (`mergeBranchOntoMain` and `detectMergeConflicts` verified via domain unit tests and web integration tests).
- [x] Conflict detection across `both_modified`, `both_added`, and `modify_delete` conflict types.
- [x] Conflict resolution strategies: 'theirs' (incoming), 'ours' (current target), and manual per-entity selection.
- [x] Dangling connection pruning: connections are retained only if both endpoint objects remain in the merged architecture state.
- [x] UI components `<ConflictResolutionBanner />` (warning alert with conflict counter and one-click strategy selectors) and `<MergeBranchModal />` (interactive 3-way merge dialog showing clean vs conflicting status, field deltas, and resolution choices).
